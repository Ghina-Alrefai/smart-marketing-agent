🤖 AI Marketing OS

نظام تشغيل تسويقي مبني على الذكاء الاصطناعي — منصّة متعددة الوكلاء (Multi-Agent System) تحوّل معلومات البراند والمنتجات إلى خطة محتوى كاملة جاهزة للنشر: نصوص وصور واعتماد بشري.

هذا المستند يشرح كل ميزة موجودة في الكود حالياً، وكيف يعمل النظام، وأين يقع كل شيء بالضبط داخل الملفات — من طبقة الوكلاء إلى الـ API إلى الواجهة الأمامية وإطار التقييم.

01 نظرة عامة على النظام

المشروع مقسوم إلى طبقتين رئيسيتين: Backend بلغة Python (FastAPI + Google Gemini) يحتوي منطق الوكلاء والـ API وقاعدة البيانات، وFrontend بـ React لإدارة البراند والمنتجات والحملات ومراجعة المحتوى المولّد.

🧩 الفكرة الأساسية

يدخل المستخدم هوية البراند + المنتجات، فيتولّى النظام آلياً بناء خطة محتوى لعدد أيام محدد، حيث يكتب لكل يوم منشوراً كاملاً (Hook + Caption + CTA + Hashtags) ويولّد له صورة تسويقية، ثم يراجع الجودة — وينتظر اعتماد المستخدم قبل النشر.

⚙️ نمط التصميم

بنية Multi-Agent: كل وكيل مسؤول عن مهمة واحدة (Single Responsibility) ويتواصل عبر Pipeline مركزي واحد. جميع الـ Prompts مركزية في ملف واحد، وكل استدعاءات النموذج تمرّ عبر خدمة LLM مشتركة (DRY).

04 المساعد الذكي عبر الشات (Orchestrator — Layer 0)

طبقة محادثة جديدة فوق الوكلاء الستة بلا أي تعديل عليهم أو على الـ Pipeline الأصلي — المستخدم يكتب طلبه بلغة طبيعية بدل تعبئة نماذج، والمُنسّق (Orchestrator) يفهم النية، يكمّل الحقول الناقصة عبر حوار قصير، ثم يستدعي الوكلاء المناسبين مباشرة.

🧭 مصنّف النية (Intent Classifier)

يحدّد إحدى 8 نيّات من رسالة المستخدم.

  • classify_intent(message, use_llm) — يجرّب LLM أولاً
  • عند فشل الاستدعاء يسقط تلقائياً لتصنيف قاعدي بالكلمات المفتاحية (صامد بلا إنترنت)
  • النيّات: WRITE_POST · CREATE_DESIGN · WRITE_AND_DESIGN · REVIEW · GET_STRATEGY · FULL_PIPELINE · GET_TRENDS · SCHEDULE_POST
📄 agents/orchestrator/intent_classifier.py

🔎 مستخرِج الكيانات (Entity Extractor)

يسحب من نص الرسالة نفسها ما يمكن فهمه تلقائياً.

  • extract_entities(message, use_llm) — اسم المنتج، عدد الأيام، نوع المنشور، نص المراجعة
  • detect_days(text) — يفهم «أسبوع» = 7، «شهر» = 30، أو رقماً صريحاً
  • النظام مخصّص لفيسبوك فقط حالياً — لا يوجد استخراج/اختيار منصّة
📄 agents/orchestrator/entity_extractor.py

🗂️ مخزن الجلسات (Session Store)

حالة الحوار بين كل رسالة والأخرى — في الذاكرة (in-memory).

  • كل جلسة: intent · slots · awaiting · options · history · cache
  • get_or_create / get / reset
  • cache يحفظ brand_guidelines لتقليل استدعاءات LLM المكرّرة
📄 agents/orchestrator/session_store.py

🧠 المُنسّق الرئيسي (Orchestrator Agent)

حلقة فهم → استكمال حقول → تنفيذ.

  • handle_message(user_id, brand_id, message, session_id, dry_run)
  • يطلب المنتج الناقص من قائمة منتجات المستخدم، ويتعامل مع حالة «منتج بلا صورة» بعرض بدائل (منتج آخر / رفع صورة / متابعة بلا صورة)
  • dry_run=true يُرجع بيانات وهمية فورية لاختبار الحوار بلا استدعاء LLM حقيقي
📄 agents/orchestrator/orchestrator_agent.py

بمجرد اكتمال كل الحقول المطلوبة، _execute() تستدعي نفس دوال الوكلاء الستة المذكورة في القسم 03 مباشرة:
