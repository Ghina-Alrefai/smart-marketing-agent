# وضع العرض دون اتصال للحملات

## الهدف

يوفّر هذا الوضع عرضاً مستقراً عندما لا يتوفر مفتاح API ممول. لا يستدعي Gemini
ولا يولّد نصاً أو صورة، ولا يسجّل استهلاكاً أو تكلفة. بدلاً من ذلك يعرض تسلسل
الوكلاء بصورة حتمية، مع إفصاح واضح في واجهة الـPipeline، ثم يحفظ بيانات حملة
براق محضّرة مسبقاً للمراجعة البشرية.

## التشغيل

القيمة الافتراضية في النسخة الحالية هي:

```env
CAMPAIGN_EXECUTION_MODE=offline_demo
CAMPAIGN_DEMO_STEP_DELAY_SECONDS=0.85
```

بعد تعديل `.env` أعد تشغيل FastAPI. عند إنشاء أي حملة:

1. تظهر شارة **Offline Demo Mode** وعبارة أن النتائج محضّرة مسبقاً.
2. تتحرك عقد التخطيط والإنتاج والتجميع بالتسلسل.
3. تُحفظ سبعة منشورات وصورها تدريجياً.
4. يبقى Scheduler في حالة **بانتظار اعتمادك**.
5. لا تنتقل أي نتيجة إلى الجدولة قبل اعتماد المستخدم.

المنشور الثامن الخاص بـQ8FA محفوظ داخل `campaign_data` كمرشح بديل، وليس منشوراً
إضافياً؛ لذلك تبقى الحملة سبعة أيام وسبعة منشورات.

## ضمان عدم استهلاك API

يتفرع `run_campaign_pipeline` إلى منفذ العرض قبل استيراد أي Agent أو عميل LLM
أو أداة توليد صور. كما يتوقف preload الخاص بنماذج Brand DNA عند تشغيل هذا
الوضع. يسجل ملخص الحملة القيم التالية بوضوح:

```json
{
  "execution_mode": "offline_demo",
  "data_source": "prepared_demo_fixture",
  "external_ai_calls": 0,
  "human_approval_required": true
}
```

## العودة إلى التوليد الحقيقي

عند توفر مفتاح API ممول:

```env
CAMPAIGN_EXECUTION_MODE=live
GOOGLE_API_KEY=your-funded-key
```

ثم أعد تشغيل الخادم. لا يحتاج الانتقال إلى تعديل الكود أو واجهة الـPipeline.

## مصدر البيانات

- النصوص: `demo_assets/alboraq/campaign.json`
- الصور: `demo_assets/alboraq/`
- النسخة: `alboraq-offline-demo-v1`

هذه البيانات مخصصة للعرض ولا تغذي Adaptive Memory، ولا تغيّر عدادات تسويق
المنتجات، ولا تدّعي وجود Prediction أو SHAP أو تقييم نموذج لم يحدث فعلياً.
