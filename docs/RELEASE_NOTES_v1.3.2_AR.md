# SmartSocial AI v1.3.2 — إصلاح توليد الحملة وحذفها

تاريخ الإصدار: 2026-08-24

## المشكلة التي عالجها الإصدار

كان من الممكن أن يعيد Gemini استجابة JSON ناقصة أثناء مرحلة الاستراتيجية أو
الأفكار. كانت الخدمة تحوّل خطأ القراءة إلى كائن فارغ، فيتابع الـpipeline بعدد
صفر من الأفكار ثم يضع الحملة في حالة `done`. لذلك تظهر الحملة مكتملة من دون
منشورات. كذلك كانت سجلات الاستهلاك المرتبطة بالخطة تمنع حذفها بسبب Foreign Key.

## الإصلاحات

- تفعيل `response_mime_type=application/json` لكل استدعاء JSON إلى Gemini.
- رفع حد الخرج الافتراضي إلى 16384 token للحملات ذات الاستجابة الطويلة.
- إعادة المحاولة ثلاث مرات عند JSON ناقص أو عقد وكيل غير صالح.
- تسجيل فشل JSON داخل Monitoring كفشل حقيقي للمحاولة، بدلاً من اعتباره استدعاءً ناجحاً.
- منع `call_llm_json` نهائياً من إعادة `{}` عند الفشل النهائي؛ يُرفع الخطأ إلى الـpipeline.
- التحقق من الحقول الأساسية والمنتجات والعدد في Strategy Agent وIdea Agent.
- منع وضع الحملة في `done` عندما تكون الأفكار أو المنشورات صفراً.
- إبقاء `done_with_errors` للحالة الجزئية فقط، عندما يوجد منشور ناجح واحد على الأقل.
- عرض رسالة الخطأ وزر إعادة التوليد عندما تصبح الحملة `failed`.
- فصل سجلات `llm_usage_logs` عن الخطة قبل حذفها، مع الاحتفاظ بسجل الاستهلاك والتكلفة.
- إضافة `ON DELETE SET NULL` لقواعد البيانات الجديدة، مع إصلاح تطبيقي متوافق مع القواعد القديمة.
- تحسين رسالة فشل الحذف في الواجهة، وإضافة تنبيه للحملة المكتملة جزئياً.

## النتيجة المتوقعة

إذا أصلح Gemini الاستجابة في محاولة لاحقة، تستمر الحملة وتُحفظ المنشورات. إذا
فشلت المحاولات كلها، تصبح الحملة `failed` مع سبب واضح ويمكن تشغيل
`إعادة توليد الحملة`. لا يمكن بعد الآن ظهور نجاح كاذب بحملة فارغة، وحذف الحملة
لا يفشل بسبب سجل الاستهلاك.
