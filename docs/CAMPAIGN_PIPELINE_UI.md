# واجهة Pipeline الحملة الحيّة

تعرض صفحة تفاصيل الحملة انتقال التنفيذ الفعلي بين الوكلاء، بدلاً من شاشة تحميل عامة. الحالة محفوظة في `ContentPlan.pipeline_state`، لذلك لا تضيع عند تحديث الصفحة أو مغادرتها والعودة لاحقاً.

## ما يظهر للمستخدم

تقسم الواجهة التنفيذ إلى ثلاثة مسارات:

1. **الفهم والتخطيط:** Orchestrator → Brand → Strategy → Product → Idea.
2. **حلقة إنتاج المنشورات:** Copywriter → Brand DNA Evaluator → Designer → Quality. تتكرر الحلقة لكل منشور، ويظهر عداد مستقل لكل وكيل.
3. **التجميع والتسليم:** Campaign Assembler → Scheduler. يبقى Scheduler في حالة `waiting_approval` حتى يعتمد المستخدم المنشورات؛ لا يوجد نشر تلقائي بلا اعتماد.

وتعرض الواجهة أيضاً:

- الوكيل النشط ووصف العملية الحالية.
- رقم المنشور الجاري من العدد الكلي.
- نسبة التقدم والزمن المنقضي.
- عدد العناصر المكتملة والمتعذرة داخل كل وكيل.
- سجل انتقالات حي مع التوقيت ومدة كل خطوة فرعية.
- العقدة التي حدث عندها الخطأ ورسالة مفهومة للمستخدم.

## عقد الحالة القادمة من الخادم

الحقل `pipeline_state` متاح في:

- `GET /api/v1/plans/{plan_id}`
- `GET /api/v1/plans/{plan_id}/status`

أهم حقوله:

```json
{
  "version": "campaign-pipeline-progress-v2",
  "status": "running",
  "active_node": "designer",
  "overall_progress": 68,
  "total_posts": 5,
  "posts_generated": 2,
  "current_post": { "index": 3, "total": 5 },
  "nodes": [
    {
      "key": "designer",
      "status": "active",
      "activity": "يبني التصميم من الفكرة المختارة...",
      "completed_items": 2,
      "failed_items": 0,
      "total_items": 5
    }
  ],
  "events": []
}
```

الحالات المدعومة للعقدة هي:

- `pending`: لم يصلها العمل بعد.
- `active`: تعمل الآن.
- `waiting`: أنهت منشوراً وتنتظر دورة المنشور التالي.
- `completed`: أنهت جميع عناصرها.
- `warning`: بعض العناصر تعذرت لكن التنفيذ تابع.
- `failed`: توقف التنفيذ عندها.
- `waiting_approval`: تنتظر قرار المستخدم قبل الجدولة.

## آلية التحديث

أثناء حالة `generating` تعيد صفحة التفاصيل طلب الخطة كل 1.5 ثانية، وتتوقف تلقائياً بعد الوصول إلى حالة نهائية. كل انتقال يحفظ Snapshot جديداً في قاعدة البيانات، وسجل الأحداث محدود بآخر 80 حدثاً حتى يبقى الرد خفيفاً حتى في حملة من 30 منشوراً.

تستمر الواجهة القديمة في العمل للحملات السابقة: إذا لم يكن `pipeline_state` موجوداً، يبني المكوّن عرضاً توافقياً من `current_stage`.
